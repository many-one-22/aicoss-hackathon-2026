# B-A01 데이터 전처리 기록

## 1. B-A01이 뭔가

관광 KVQA 데이터셋 중 **광주·전남 음식점** 부분. 원래는 이미지+질문답변용 AI 데이터인데, 우리는 **식당 기본정보(상호·메뉴·주소·좌표)** 를 추출해서 "남도 식탁 큐레이터"의 식당 DB로 쓴다.

## 2. 원본 데이터 구조

```
B-A01/
├── Train/       (TL_ 접두사)
│   ├── QA(질문답변)     ← 상호·메뉴·주소·좌표, 질문 반복 많음
│   ├── 트리플           ← 정제된 사실 [상호,관계,값], BOM 있음, 좌표 없음
│   └── 이미지캡셔닝      ← 이미지 설명문 (미사용)
└── Validation/  (VL_ 접두사, 동일 구조)
```

**파일 개수**

| 종류 | Train(광주/전남) | Validation(광주/전남) |
|---|---|---|
| QA | 3,528 / 8,450 | 441 / 1,057 |
| 트리플 | 21,820 / 10,661 | 2,728 / 1,333 |
| 이미지캡셔닝 | 17,640 / 42,250 | 2,205 / 5,285 |

**세 종류 비교**

| 종류 | 내용 | 좌표 | 용도 |
|---|---|---|---|
| QA | 메뉴·주소·연락처·영업시간·주차 (같은 질문 5~6회 반복) | O | 좌표 확보 |
| 트리플 | 같은 정보를 정제된 사실로, 반복 없음 | X | 기본정보 주력 |
| 이미지캡셔닝 | 이미지 설명만 | - | 미사용 |

## 3. 핵심 설계 원칙: 필터링(삭제) 대신 태깅(라벨링)

향토 키워드 없다고 식당을 **버리면 진짜 향토식당도 유실**된다. 그래서 **전부 적재하고 이름표(cuisine_type 등)만 붙인다.** "향토음식점"은 삭제 기준이 아니라 나중에 조회로 골라내는 **속성**.

## 4. 처리 파이프라인 (2단계)

```
Step 1. 병합  (scripts/merge_ba01.py)
   트리플(기본정보 뼈대) + QA(좌표) 를 합침
   → TL 25,275 / VL 4,370 고유 식당

Step 2. 태깅  (scripts/tag_cuisine.py)
   각 식당에 cuisine_type(요리계열) 라벨 부여
   → 한식/중식/양식/일식/카페/치킨/주점
```

- **뼈대는 트리플** (식당의 2/3가 트리플에만 존재, QA엔 없음)
- **QA는 좌표 채우기 + 정보 보완** (좌표는 QA에만 있음)
- **TL/VL은 절대 안 합침** (모델 학습/평가 분리 목적)

## 5. 처리 중 발견한 데이터 함정 (전부 대응함)

| # | 함정 | 대응 |
|---|---|---|
| 1 | 트리플 파일에 **UTF-8 BOM** | `utf-8-sig`로 읽음 |
| 2 | **상호명에 쉼표 있는 식당의 트리플이 원본에서 깨짐** (예: `효천1,2지구점` → 필드 밀림). AI-Hub 원본 버그, 다운로드 문제 아님(파싱실패 0건) | triple 길이!=3 스킵 + 관계 화이트리스트로 걸러냄 |
| 3 | 트리플의 "판다"(업종) 필드는 **전체의 4%만** 존재 → 분류 근거로 못 씀 | 메뉴 텍스트를 주력 신호로 사용 |
| 4 | "없음" 값이 **주차 17,780건 / 연중무휴(휴무일=없음) 11,623건** — 버리면 정보 손실 | "알수없음"만 버리고 "없음"은 보존 |
| 5 | 일부 식당 메뉴가 여러 트리플에 분산 (0.4%) | 메뉴는 아이템 단위로 합침(union) |
| 6 | **같은 식당이 두 POI_id로 중복** (18xxxx↔42xxxx 등). 좌표는 한쪽에만 붙음. TL 4,161행 | `(상호, 주소)` 정확일치로 병합 |
| 7 | **이름 표기만 다른 중복** (`본죽 광주송정점` vs `본죽 광주송정점 2`). 주소+전화 동일. 약 3,748행 | `(주소, 숫자전화)`로 2차 병합 |
| 8 | 원본 좌표가 **위경도 반대** (mapx≈35=위도, mapy≈126=경도) | 명시적 `lat`/`lng` 컬럼으로 출력 |
| 9 | **(0,0) 무효좌표 88개** | 0 제외 + 한국범위(위33~39, 경124~132) 검증 |
| 10 | 병합 후 대표 상호명에 `" 2"` 접미사 남음 | 형제 이름 중 접미사 없는 걸 우선 선택 |

> 중복(6+7) 합치면 전체의 약 24%가 중복이었음. **POI_id 단독으로 식당을 식별하면 안 된다.**

## 6. 코드리뷰로 잡은 버그들 (2~3회 리뷰)

**병합 스크립트**
- 중복 POI 병합 누락(핵심) → 2단계 병합으로 해결
- 빈 split ZeroDivision → 가드
- glob 정렬 안 됨(재현성 깨짐) → `sorted()`
- 복합질문("영업시간 및 휴무일") 오분류 → 주제어 2개 이상이면 스킵
- 좌표 첫 이미지만 보고 None도 채움 → 유효좌표 나올 때까지 순회

**태깅 스크립트**
- `마라`가 "고구마**라떼**"에 오매칭 → `마라탕/마라샹/마라상/마라향`으로 구체화
- 아메리카노/라떼가 카페 키워드에 없어서 **카페 1,390개가 한식에 숨어있었음** → 카페 신호 확장
- `밥버거`(분식)가 양식으로 → 밥버거는 양식 제외
- `죽`이 상호명 `죽림/죽녹원/가죽`에 오매칭 → STRONG_KOREAN은 **메뉴에서만** 검사
- `빙수`가 `웰빙수제비`에 오매칭 → 수제비 등을 한식메인에 추가
- 곰탕/칼국수+커피 파는 한식당이 카페로 유출 → STRONG_KOREAN에 곰탕·설렁탕·칼국수·곱창·전골·백숙·수제비 추가
- (독립 서브에이전트 리뷰) `오리`가 `오리지날/오리엔탈`에 오매칭 → 오리탕/오리불고기 등 구체 요리명으로
- (리뷰) 브랜드카페(빽다방·스타벅스…)가 키워드 회피해 한식으로 샘 → CAFE_SIGNAL에 브랜드명 추가
- (리뷰) tag_cuisine 단독 재실행 시 뒤 태그 컬럼 소실 → `run_tags.py` 러너로 순서 강제

## 7. 태깅 3종 (라벨 부여, 삭제 없음)

| 태그 | 값 | 방식 | 커버리지 |
|---|---|---|---|
| `cuisine_type` | 한식/중식/양식/일식/카페/치킨/주점 | 상호+메뉴 우선순위 키워드, 한식 기본값 | 전체 |
| `ingredient_category` | 해산물/육류/채소 (멀티라벨) | 메뉴 재료 사전 매칭 | 한식의 76.1% |
| `local_score` | 남도 향토 점수 0~5 | (한식·주점) 대상, 향토 키워드 개수 | - |

- **핵심 판단**: 재료·향토는 승인데이터(B-P07/KAMIS 부류)가 메뉴의 37.6%만 커버 → cuisine_type과 동일하게 **메뉴 기반 처리사전**으로 구성 (짜장→중식과 같은 논리).
- **local_score 게이트**: cuisine_type이 한식 또는 주점일 때만 점수(그 외 0). 주점 포함 = 남도 포차 문화(홍어삼합 포차 등)가 향토라서.
- **local_score 그라데이션**: 0=일반 / 1=향토 특색 / 2+=향토 뚜렷. 딱 자르지 않고 랭킹용.

## 8. 최종 산출물

**파일** (`Data/ba01/`)
```
ba01_TL_merged.json / .csv      ← 병합 결과 (Train, 25,275)
ba01_VL_merged.json / .csv      ← 병합 결과 (Validation, 4,370)
ba01_TL_tagged.json / .csv      ← 태그 3종 포함 (Train)
ba01_VL_tagged.json / .csv      ← 태그 3종 포함 (Validation)
debug/                          ← 병합·분류 리포트 로그
```

**레코드 스키마 (한 식당 = 한 줄, 14필드)**
```
poi_id, place, area, lat, lng, menu, address, phone,
hours, closed_days, parking, cuisine_type, ingredient_category, local_score
```
- `poi_id`는 병합된 경우 `186403|426816|879976`처럼 원본 id를 모두 보존.
- `주차시설="없음"`=주차불가, `휴무일="없음"`=연중무휴 (빈칸=정보없음과 구분).

**분포 (TL+VL 29,645)**
- cuisine_type: 한식 16,098 / 카페 7,227 / 치킨 1,762 / 양식 1,435 / 주점 1,255 / 중식 1,171 / 일식 697
- ingredient_category: 육류 9,754 / 해산물 6,185 / 채소 2,995 (멀티라벨, 중복카운트)
- local_score≥1 (향토): 2,398 (한식 2,312 + 주점 86)

## 9. 남은 작업 (가격 기능, 나중)

가격 데이터(B-P01 KAMIS / B-P07)는 "제철 특산물 가격" 기능용 → 그 기능 만들 때 확보. **낙지·꼬막·홍어 등 남도 대표 수산물은 어느 승인 데이터에도 가격이 없음**(확인 완료) → 구할 수 있는 품목으로만.
- B-P07: 전국 평균, 2024 1년, 육류 없음 → 약함
- B-P01(KAMIS): 광주/순천 지역, 농·수산 다년 월별 O, 축산물은 축평원(ekapepia)으로 이전

## 10. 재현 방법

```bash
python scripts/merge_ba01.py   # 병합 → Data/ba01/ba01_*_merged.*  (원본 바뀔 때만)
python scripts/run_tags.py     # 태그 3종 순서 실행 → ba01_*_tagged.*
```
> 태그 스크립트는 반드시 `run_tags.py`로 순서 실행(cuisine→ingredient→local). 단독 재실행 금지.
