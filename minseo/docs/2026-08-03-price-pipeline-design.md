# 식재료 시세 안내 파이프라인 설계 (Core)

작성일: 2026-08-03
관련 데이터: B-P01(KAMIS 농·수산 소매가격), B-A01(식당·메뉴), B-A07(음식명)

## 1. 목적 & 스코프

식당의 향토음식 메뉴에서 핵심 식재료를 뽑아, 그 재료의 **현재 시세·최근 추이·제철 여부**를 안내한다. 서비스 핵심기능 "식재료 산지·시세 안내"의 가격 부분.

**스코프 (해커톤 수준)**
- ✅ **Core (빌드 대상)**: 재료 추출 → KAMIS 매칭 → 현재 시세 + 최근 12개월 추이 + 제철 판정
- 🔮 **Stretch (발표 비전, 여유 시 대표 1개만)**: Prophet 미래 가격 예측
- 데이터: KAMIS **수동 스냅샷** (필요 품목만 다년 월별)
- 지역: **광주 + 순천(전남 대표)** — KAMIS 소매가 조사 도시가 광주·순천뿐 (목포·여수·나주 없음). 순천을 전남 시세 대리값으로 사용.

**명시적 Out of scope**
- Prophet 전체 품목 예측 (stretch)
- 실시간 오픈API 연동 (수동 스냅샷으로 대체, 추후 자동화)
- 낙지·꼬막·홍어 등 남도 특산 수산물 시세 (어느 승인데이터에도 없음 → 전통시장 안내로 우회)
- 산지(origin) 정보 (별도 데이터 필요, 이 스펙 범위 밖)

## 2. 데이터 흐름

```
[식당 메뉴 / 음식명]
   │ ① 재료 추출 (dish → 핵심 재료, KAMIS 품목 단위)
   ▼
[핵심 재료: 고등어, 배추, 돼지 …]
   │ ② 매칭 (재료 → KAMIS 품목명)
   ▼
[KAMIS 월별 가격 시계열 (광주/순천, 다년)]
   │ ③ 제철·추이 계산
   ▼
[출력: 현재시세 · 12개월 추이 · 제철뱃지  |  없으면 전통시장 안내]
```

## 3. 컴포넌트 (각각 독립·테스트 가능)

### ① 재료 추출 사전 — `build_ingredient_map.py`
- **입력**: 우리가 다루는 음식/메뉴 텍스트 (B-A01 메뉴, B-A07 음식명)
- **처리**: dish 키워드 → **KAMIS에 존재하는 구체 품목**으로 매핑. cuisine/ingredient 태깅과 같은 손수 사전(처리로직).
  - 예: `고등어조림→고등어`, `갈치조림→갈치`, `김치·배추전→배추`, `삼겹살·제육→돼지`, `콩나물국→콩나물`
  - 카테고리(해산물)가 아니라 **KAMIS 품목명 단위**로 추출하는 것이 핵심 차이.
- **출력**: `Data/price/ingredient_map.csv` (`dish_keyword, kamis_item`)
- **의존**: KAMIS 품목 목록(②에서 확정)

### ② KAMIS 가격 테이블 — `build_price.py`
- **입력**: KAMIS 통계 페이지 수동 다운로드 엑셀 (품목별, 광주·순천, 다년 월별)
- **처리**: 정제 → long 포맷 통일, 인코딩·결측 처리
- **품목 범위**: 우리 메뉴 재료 중 KAMIS에 있는 것만(~30~40품목). 전체 100+ 아님.
- **출력**: `Data/price/price_monthly.csv` (`item, region, year_month, price, unit`)

### ③ 제철·추이 계산 — `seasonality.py`
- **입력**: `price_monthly.csv`
- **처리** (품목·지역별). 아래 3개 지표를 명확히 구분해 계산:
  - **현재 시세** = 최신 월 가격
  - **최근 추이** = 최근 12개월 (item, region) 가격 배열
  - **현재수준** (저렴/평균/비쌈) = 현재가를 *그 품목의 전체 과거 가격 분포* 백분위로 판정. 하위 33% = 저렴 / 중간 = 평균 / 상위 33% = 비쌈.
  - **제철 여부** = *캘린더 달 단위* 판정. 각 달(1~12월)의 과거 중앙 가격을 구해, 가장 싼 2~3개월을 그 품목의 "제철"로 정의. 현재 달이 거기 속하면 제철뱃지 ON.
  - → "현재수준"은 지금 시점 vs 전체 역사, "제철"은 지금 달 vs 연중 계절패턴. 서로 다른 축.
- **출력**: `Data/price/seasonality.json` (품목·지역별: 현재가, 최근12개월배열, 현재수준, 제철달목록, 현재제철여부)

### ④ 통합 조회 — `price_lookup.py`
- **입력**: 식당 레코드(또는 메뉴 텍스트) + area(광주/전남)
- **처리**: 메뉴 → 재료 추출(①) → KAMIS 품목 매칭(②) → seasonality(③) 조회. area가 전남이면 순천, 광주면 광주 시세 사용.
- **출력**: 메뉴별 `{재료, 현재시세, 12개월추이, 제철여부, 현재수준}` 또는 `{시세미제공, 전통시장안내}`(낙지·꼬막 등)

## 4. 산출물

```
Data/price/
├── price_monthly.csv      ← KAMIS 정제 시세 (광주·순천, 다년 월별)
├── ingredient_map.csv     ← dish키워드 → KAMIS품목
└── seasonality.json       ← 품목·지역별 제철·현재수준
scripts/
├── build_price.py
├── build_ingredient_map.py
├── seasonality.py
└── price_lookup.py
```

## 5. 엣지 처리
- **시세 없는 재료**(낙지·꼬막·홍어·매생이): 에러 아니라 `시세미제공 + 전통시장 안내`로 반환
- **매칭 안 되는 메뉴**(재료 추출 실패): 시세 섹션 생략 (식당 추천 자체엔 영향 없음)
- **결측 월**: 추이 그래프에서 빈 구간 처리, 제철 판정은 가용 데이터로

## 6. 성공 기준
- 대표 재료(고등어·갈치·배추·돼지 등 ~30품목) 광주·순천 다년 월별 시세가 `price_monthly.csv`에 적재됨
- 식당 하나 넣으면 메뉴별 재료의 현재시세·추이·제철뱃지가 반환됨 (해피패스: 고등어조림 → 고등어 → 광주 시세·제철)
- 시세 없는 재료는 전통시장 안내로 우회 (크래시 없음)
- 제철 판정이 실제 계절 패턴과 상식적으로 일치 (예: 배추 겨울 저렴)
